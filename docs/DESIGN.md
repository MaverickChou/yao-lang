# 爻 · 设计决策记录

> 这份文档只记录**为什么**，不记录**是什么**。语法与语义见 [SPEC.md](../SPEC.md)。
>
> 一条总约束贯穿全部决策：**6 位**。它不是实现细节，是这门语言的全部。

---

## 1. 为什么是状态机语言，不是通用语言

**备选**：做一门通用脚本语言，用 64 个卦名当关键字。

**否决理由**：6 位只有 64 个值，做不了字符串、堆、GUI。硬撑的结局是变成
「用卦名装饰的 Python」——所有真实功能都靠宿主逃生口，卦反而成了负担。

**选择**：只做真实软件里最难写、最容易错的那部分——**状态机**，其余交给宿主语言。

**代价**：爻不能独立成程序，必须被嵌入。这是刻意的，写进了 README 的第一段。

---

## 2. 为什么是 6 位

`2^6 = 64`，与六十四卦的数量重合。

如果用 8 位，64 卦只占一半，另一半状态**没有卦名**——语言里会出现"无名状态"，
与"每一卦都有名字、都有义"的立意直接冲突。用 4 位又装不下。

**代价**：数据宽度极小，任何超过 63 的数都表示不了。
**后果**：内存模型只能是"卦序列"，地址也是 6 位——整机 64 格 × 6 位 = 384 bit。

---

## 3. 为什么初爻是 bit0

**备选**：上爻 = bit0（符合"自上而下"的阅读顺序）。

**否决理由**：`综`（爻序倒转）会变成"位反转 + 偏移"，`变数`（动爻数）也不再是
popcount。所有公式都得带一个常数修正项，每处都是错的机会。

**选择**：`bit0 = 初爻`。`综` 退化为一次位反转，`变数` 退化为一次 popcount。

**验证**：56 条"某卦之互卦为某卦"的古籍记载，由

```
互(x) = ((x>>1)&7) | (((x>>2)&7)<<3)
```

一行公式全部复现，代码里**没有任何互卦表**。见 `tests/core.test.js`。
写错一位，这 56 条全崩。

---

## 4. 为什么 `变` 是 12 位，而不是「卦 + 动爻数组」

**备选**：状态就是 6 位卦，动爻另存一个字段。

**否决理由**：两处状态就要同步，同步就要靠约定，约定就会破。而"本卦、动爻、之卦"
三者的关系是一条**代数恒等式**，不该靠约定维护。

**选择**：

```
变 = (动 << 6) | 本        12 位
之 = 本 ^ 动
```

于是 `本 ⊕ 动 ⊕ 之 = 0` 成了构造器不变式——不可能拼出一个自相矛盾的卦变。

**代价**：状态空间从 64 变成 4096。
**好处**：4096 仍然可以完全穷举；而且占卜与普通计算共用一个类型。

---

## 5. 为什么按「本卦」匹配状态，而不是按 12 位整值

若按整值匹配，同一间房的 8 种「动」会变成 8 个不同状态，一条规则要写 8 遍，
`转 * 行 -> ...` 也就无法一次覆盖全部 64 卦。

按 `本` 匹配 ⇒ 一条规则铺满 64 个状态。地牢的 4 条规则就是这么来的。

**代价**：两个声明的态不能有相同的本卦（诊断 `Y0101`）。这是真实约束，不是缺陷。

---

## 6. 为什么卦名占掉 64 个标识符

**备选**：卦名只作字面量，用户仍可用 `泰` 当变量名。

**否决理由**：`泰` 同时可能是变量和字面量，解析就要上下文相关；而上下文相关是
语言设计里最容易长成沼泽的地方。

**选择**：64 个卦名一律保留字。但**名字位置**（`态` 名、`转` 的源、`起`）豁免，
所以 `态 未济 = 未济` 能写，读起来就是一部卦变史。

**副作用**：`否` 与 else 冲突 → else 改叫 `否则`。
由此定下一条：**与卦名冲突的关键字必须加字或换写，不得驱逐卦名。**

---

## 7. 为什么爻串是规范字面量，卦象字符只是糖

| | 爻串 `987789` | 卦象 `䷾` |
|---|---|---|
| 输入 | 任何键盘 | 需要输入法或码表 |
| 字体 | 一定有 | 大概率豆腐块 |
| diff / grep | 可读 | 乱码 |
| 可读性 | 易学界通用记法 | 好看 |

**决策**：源码 ASCII，卦象字符只做显示层。`yao fmt` 默认规约到爻串。

**消歧依据**：本语言 `数` 只有 0–63，所以「6 位、每位 ∈ {6,7,8,9}」的数字串
绝不可能是数字，无需任何前缀或括号。

---

## 8. 为什么占卜不进求值语义

**否决理由**：一旦 `筮` 参与求值，同一个程序两次运行结果不同——测试、验证器、
可复现性全部失效。那等于用一个花招毁掉整个工程的可靠性。

**选择**：
- `筮` 是唯一随机源，**必须**显式传种子，同种子同结果
- `断` 是纯函数（七分支按 `变数` 分发）
- 辞是数据，不进编译器

**后果**：CLI 每次起卦都打印种子，任何一卦都能复现。

---

## 9. 为什么验证器是穷举，而不是抽象解释

4096 个状态、几个事件、每个事件最多 6 个参数——一次 BFS 就走完了。
这是 6 位换来的唯一"免费超能力"，必须做成卖点而不是藏起来。

`yao check` 因此能给出**精确**答案：可达集、死态、未定义转移、强连通分量、图直径。

**边界**（写死在 SPEC §9.3）：组卦 N ≥ 4 时禁止宣称穷举，必须退化为有界检验。
这条是防后期吹牛的闸。

---

## 10. 为什么第一个后端是 C99

**备选**：字节码 VM（最纯正）、WASM（最时髦）。

**选择 C 的理由**：零依赖、输出可读可调试、能被任何真实项目 `#include`、
任何平台都有编译器。

**验收标准不是「能生成」**，而是：`gcc -std=c99 -Wall -Wextra -Werror` 零警告，
且**与解释器逐事件轨迹一致**。见 `tests/c-equivalence.test.js` 与 SPEC §14.3。

这条标准上线当天就抓到两个真 bug（`变数` 被提前投影成卦、`合` 的混合位宽）。

---

## 11. 为什么不写 WASM 后端

内核是纯 JS，把数据内联进一个 HTML 的成本，比写一套 WASM codegen 低一个数量级。

WASM 能证明的只有"能编译到 wasm"，不增加任何用户价值。
所以网页版用打包（`tools/build_web.mjs`），WASM 后端留作 M7 的技术展示。

**副产品**：打包器把两处 `node:fs` 替换成内联数据，替换点找不到就直接报错——
不允许静默产出一个只能在 Node 跑的包。

---

## 12. 为什么辞库标 draft 而不是不发布

450 条卦辞爻辞是凭记忆转录的，必然有出入。三条路：

1. 不发布 → 占卜功能是空的
2. 发布且不标注 → 假
3. **发布 + 五处标注 + 逐条签字机制**

选了 3：`status: draft`、CLI 每次提示、`corpus.NOTES.md` 专页、README 顶部警示、
测试断言「已校对 + 未校对 = 450」不缺项。

原则：**宁可不体面地承认，也不做看起来像真的假东西。**
签字簿 `data/corpus.verified.txt` 目前是空的——一条都没核过。

## 明确否掉的方案

| 方案 | 为什么不行 |
|---|---|
| 按卦义给 64 个卦各配一个功能 | 得到 64 路 switch，无代数结构，学不会也组合不了 |
| 允许 `卦 + 1` 这类隐式转换 | 6 位语义立刻退化成 int，全部古典约束失效 |
| 把卦辞编进编译器 | 数据混进代码，改一个字要重新编译 |
| 把 `@筮` 做成求值的一部分 | 见 §8，毁掉可测试性 |
| 文档里暗示已支持未实现的东西 | 见 SPEC §14「已知缺口」——这是硬规矩 |

## 工程坑（踩过的，写下来免得再踩）

| 坑 | 现象 | 解法 |
|---|---|---|
| 中文路径 + MinGW | `ld` 报 `cannot find crt2.o` | 工具链与构建目录放纯 ASCII 路径 |
| `.cmd` 写中文 | 引号被截断，报 `'st' 不是命令` | 启动器保持纯 ASCII |
| `.cmd` 用 LF | 字符被吞 | 强制 CRLF（`.gitattributes`） |
| 打包 ESM 别名 | `import { dong as dongOf }` 剥掉后 `dongOf` 未定义 | 打包器补 `const dongOf = dong` |
| `变数(本)` 恒为 0 | 卦无动爻 | 加裸 `变` 表示整个 12 位状态 |
| Pages 分支部署 | 只有 `/` 和 `/docs` 两个选项 | 产物输出到 `docs/` |
