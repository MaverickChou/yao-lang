## 0. 一分钟

爻是一门 **6 位状态机语言**：程序是若干状态与转移，编译成 C 或直接在解释器里跑。

```yao
机 闸机 {
  事 投币
  事 通过

  态 闲   = 坤
  态 放行 = 复

  转 闲   投币 -> 放行
  转 放行 通过 -> 闲

  起 闲
}
```

六十四卦正好是 6 个比特。一卦就是 6 位，一爻就是一位。这不是装饰——
`错`、`综`、`互` 全部退化成位运算（见 §3.4）。

## 1. 安装

需要 **Node.js ≥ 20**。没有其他依赖，不需要 `npm install`。

### Windows

```bat
git clone https://github.com/MaverickChou/yao-lang.git
cd yao-lang
yao
```

`yao.cmd` 会自动找 Node（仓库内 `runtime\` → `C:\Program Files\nodejs` → PATH），
并把控制台切到 UTF-8，否则卦象字符会乱码。

### Linux / macOS

```bash
git clone https://github.com/MaverickChou/yao-lang.git
cd yao-lang
./bin/yao.js
```

### 不装任何东西

直接玩网页版：**https://maverickchou.github.io/yao-lang/**

## 3. 语言参考

### 3.1 字面量

一个卦字面量有四种等价写法：

| 写法 | 例 | 说明 |
|---|---|---|
| 爻串 | `987789` | **规范形式**。六个字符，自初爻至上爻，取值 6/7/8/9 |
| 卦名 | `既济` | 简体规范名；繁体与异体自动归一（`既濟` → `既济`） |
| 卦象字符 | `䷾` | U+4DC0–U+4DFF，按文王序 |
| 加动爻 | `既济/初上`、`既济/100001` | 斜杠后是动爻掩码，**必须紧邻**，中间不能有空格 |

爻串的四个数字就是**四象**：

| 数 | 名 | 阴阳 | 动静 |
|---|---|---|---|
| 9 | 老阳 | 阳 | **动**，变阴 |
| 7 | 少阳 | 阳 | 静 |
| 8 | 少阴 | 阴 | 静 |
| 6 | 老阴 | 阴 | **动**，变阳 |

`987789` 的意思是：初爻老阳、二爻少阴、三爻少阳、四爻少阳、五爻少阴、上爻老阳。

### 3.2 类型

| 类型 | 值域 | 说明 |
|---|---|---|
| `变` | 0–4095 | 核心类型，12 位 |
| `卦` | 0–63 | `变` 的子类型，恒有 `动 = 0` |
| `数` | 0–63 | 算术值，与 `卦` **不能**隐式互转 |
| `爻` | 6/7/8/9 | 四象 |
| `位` | 1–6 | 爻位 |

**`变` 是全部**：低 6 位是本卦，高 6 位是动爻掩码，之卦由两者导出：

```
之 = 本 ^ 动
```

### 3.3 内置函数

| 函数 | 结果 | 说明 |
|---|---|---|
| `本(x)` `动(x)` `之(x)` | 卦 | 三个投影 |
| `静(x)` | 卦 | 丢掉动爻 |
| `变(本, 动)` | 变 | 构造 |
| `错(x)` `综(x)` `互(x)` | 卦 | 六爻全变 / 爻序倒转 / 互卦 |
| `变数(x)` | 数 | 动爻个数 0–6 |
| `当位(x)` | 数 | 当位爻数 0–6 |
| `序(x, 先天\|文王)` | 数 | 先天 0–63；文王 1–64 |
| `卦(n)` `数(x)` | — | 显式转换 |
| `爻(x, i)` | 爻 | 第 i 爻的四象 |

三个投影可以直接用**裸名**，作用于当前状态：

- 裸 `本` = 当前状态的卦体（6 位）
- 裸 `变` = 当前状态的整个 12 位值

> ⚠️ `变数(本)` 恒为 0——`本` 是卦体，卦体的动爻恒为 0。
> 要数整个状态的动爻，写 `变数(变)`。

### 3.4 位运算与古典概念

| 古典 | 位运算 | 例 |
|---|---|---|
| 错 | `x ^ 0b111111` | 既济 ⇄ 未济 |
| 综 | 六位反转 | 泰 ⇄ 否 |
| 互 | `((x>>1)&7) \| (((x>>2)&7)<<3)` | 既济 → 未济 |
| 变 | `本 ^ 动` | 老阳变阴、老阴变阳 |

56 条「某卦之互卦为某卦」的古籍记载由这一行公式自动复现，代码里没有互卦表。

### 3.5 运算符

```
算术   +  -  *          （全部 mod 64，无除法）
位     &  |  ^  ~  <<  >>
比较   ==  !=  <  >  <=  >=      结果是 1 或 0，不是布尔类型
```

### 3.6 语句

```
机 名 { ... }            机器，一个文件一个
事 名                    事件
事 名(位 n)              带参数的事件，参数 1..6
态 名 = 表达式            态（必须是常量表达式）
转 源 事件 -> 目标        转移；源写 * 表示通配
起 态名                  起始态，必须有且只有一个
```

**态名可以出现在目标位置当常量**：

```yao
态 闲 = 坤
转 某 投币 -> 闲        # 等价于 -> 变(0, 0)
```

**名字位置可以写卦名**（`态` 名、`转` 的源、`起`），所以 `态 未济 = 未济` 合法。

### 3.7 表达式：合、若、块

**合** —— 按值分发，必须有 `_` 兜底：

```yao
转 * 行 -> 合 变数(变) {
  0 => 本,
  6 => 变(本, 0),
  _ => 变(本 ^ (1 << (n - 1)), 1 << (n - 1))
}
```

**若** —— 条件非零为真，两臂必写：

```yao
转 * 走 -> 若 变数(变) == 6 { 乾 } 否则 { 变(本, 0) }
```

`否则` 而非 `否`——`否` 是第 12 卦（同理，所有与卦名冲突的词都加字或换写）。

**组** —— 多组件机器。每个组件持有若干命名的卦，总状态 64^N：

``yao
组 前 { 关 = 坤  开 = 复 }
组 后 { 关 = 泰  开 = 否 }
转 前.关 前投币 -> 前.开
起 前.关, 后.关
``

一个事件只能属于一个组件（编译期检查），所以运行期没有歧义。

**块与印** —— 转移目标可以是块，块里的 印 向宿主输出：

```yao
转 * 走 -> {
  印 1;
  印 本 + 2;
  变(本, 0)
}
```

`印` 只能在语句位置、必须以分号结尾，**因此它的值不可能影响目标状态**。
这是刻意的：状态轨迹始终可复现，`yao check` 的穷举始终有效。

## 4. 验证

```bash
yao check 机器.yao
```

把 4096 个可能状态全部走一遍，报告：

| 项 | 含义 |
|---|---|
| 可达态 | 从起点出发真正能到达多少个状态 |
| 态可达 | 声明的态里有多少个走得到（少于此数会报 Y0203） |
| 死态 | 走不出去的状态（Y0204） |
| 未定义转移 | 哪些 (态, 事件) 组合没写规则 |
| 强连通 | 图是否强连通 |
| 图直径 | 最大分量内的最长最短路；非强连通或分量过大时显式标注「已跳过」 |

选项：

```bash
yao check 机器.yao --strict    # 有问题时退出码 1（CI 用）
yao check 机器.yao --json      # 机器可读
```

## 5. 编译到 C

```bash
yao build 机器.yao -o 机器.c
yao build 机器.yao --header -o 机器.c    # 同时生成 机器.h
yao build 机器.yao --main -o 机器.c      # 附带一个极简命令行宿主
```

生成的接口：

```c
void     yao_init(uint16_t *s);
int      yao_step(uint16_t *s, uint16_t ev, uint8_t p0);   /* 0 成功，1 无定义 */
uint16_t yao_state(uint16_t s);
```

宿主只需要持有那个 `uint16_t`、在事件发生时调用 `yao_step`。

```c
#include <stdio.h>
#include "机器.h"

int main(void) {
  uint16_t s;
  yao_init(&s);
  printf("初始 %04X\n", (unsigned)s);
  if (yao_step(&s, EV_0, 0) == 0) printf("现在 %04X\n", (unsigned)s);
  return 0;
}
```

**生成的代码不知道状态的含义**。`0x28` 是"南北绿、还剩 5 秒"还是别的，由宿主解释。
完整例子见 [`examples/traffic/`](../examples/traffic/)。

> 构建提示：`机器.h` 与包含它的 `.c` 必须在同一目录（引号包含只搜当前文件所在目录）。
> Windows 上仓库路径若含中文，MinGW 的 ld 会找不到 `crt2.o`——把生成物放到纯 ASCII 目录再编译。

## 6. 占

```bash
yao divine                    # 掷金钱卦并断
yao divine --seed=42          # 可复现
yao divine --法=大衍          # 换起卦法
yao divine 泰/100001          # 指定卦变
yao corpus                    # 辞库覆盖与校对状态
yao corpus --unverified       # 列出未校对条目
```

**七分支断法**按动爻数分发：

| 变数 | 断法 |
|---|---|
| 0 | 本卦卦辞 |
| 1 | 本卦该动爻爻辞 |
| 2 | 本卦两动爻爻辞，以上爻为主 |
| 3 | 本卦与之卦卦辞，本卦为主 |
| 4 | 之卦中两不变爻，以下爻为主 |
| 5 | 之卦中不变爻 |
| 6 | 乾坤用九用六；余卦取之卦卦辞 |

两法分布不同，不能混：

| 法 | 老阴 6 | 少阳 7 | 少阴 8 | 老阳 9 |
|---|---|---|---|---|
| 金钱 | 1/8 | 3/8 | 3/8 | 1/8 |
| 大衍 | 1/16 | 5/16 | 7/16 | 3/16 |

> **辞库是草案。** 450 条结构已机器校验，并与一份外部转录做过逐字比对
> （448 条中 417 条仅标点不同），但**没有逐字校对纸本**，`corpus.verified.txt` 仍是空的。
> 详见 [../data/corpus.NOTES.md](../data/corpus.NOTES.md)。

## 10. 能做什么，不能做什么

**适合**：嵌入式状态机、协议握手、设备控制、游戏行为、流程引擎。

**不适合**：字符串处理、堆分配、GUI、通用计算。

单机 64 个状态，这是硬边界。需要更大空间要靠多态组合（`组`，尚未实现）。

| 限制 | 状态 |
|---|---|

| 辞库校对 | 450 条 0 条已核 |

## 5b. 编译到 WASM

```bash
yao build 机器.yao --target=wasm -o 机器.wasm
```

```js
const mod = await WebAssembly.instantiateStreaming(fetch("机器.wasm"));
const { init, step } = mod.instance.exports;

let s = init();              // 起始状态
s = step(s, 1, 0);           // 事件 1，参数 0；返回 -1 表示此路不通
```

导出三个符号：`init()`、`step(state, ev, arg)`、`memory`。

**这不是把表达式编译成指令，而是部分求值**：状态空间只有 4096，构建时用解释器
把整张转移表算出来，模块里只有一个查表函数。带参数的事件占 6 列（arg 1..6）。

| 机器 | 模块大小 |
|---|---|
| 交通灯（2 个事件，无参） | 16 KB |
| 地牢（4 个事件，其中 1 个带参） | 72 KB |

限制：组机器暂不支持（会明确报错），事件号从 1 开始，与 `EV_i = i + 1` 一致。
