# 交通灯

第一个**真的编译成 C 并链接成二进制**的程序：状态机用爻写，宿主用 C 写。

```bash
yao build traffic.yao --header -o traffic.c
gcc -std=c99 -Wall -Wextra -Werror traffic.c host.c -o traffic
./traffic
```

## 6 位怎么装下一盏灯

没有变量，也没有计数器。倒计时就存在状态自己的高三位里：

```
bit 0-2   相位：0 南北绿 / 1 南北黄 / 2 全红 / 3 东西绿 / 4 东西黄
bit 3-5   剩余秒数
```

于是「绿灯 5 秒」不是一个计时器，而是一个数：`0 | (5 << 3)` = 40。
每秒把它减一，减到 0 就换相位——**换相位的逻辑本身就是状态转移**。

```yao
转 * 秒 -> 合 (本 >> 3) {
  0 => 合 (本 & 7) {          # 倒计时归零：按相位换灯
    0 => 变(1 | (2 << 3), 0),
    ...
  },
  _ => 变((本 & 7) | (((本 >> 3) - 1) << 3), 0)   # 否则减一
}
```

`合` 嵌套两层：先看高三位（还有时间吗），再看低三位（该转哪一相）。

## 分工

机器只知道一个 6 位数。**「哪几位是灯」是宿主的解释**：

```c
const char *ns = phase == 0 ? "G" : phase == 1 ? "Y" : "R";
const char *ew = phase == 3 ? "G" : phase == 4 ? "Y" : "R";
```

这是 SPEC §10 定下的分工：状态机是纯函数，宿主负责一切 I/O。

## 这个 demo 证明了什么

- 爻能编译出一个**被真实程序链接**的状态机，不是一个只会打印状态的玩具
- 3+3 位域挤在 6 位里，说明小状态空间可以编码得很密
- 同一个 .yao 在解释器和 C 里跑出同一条轨迹（`tests/c-equivalence.test.js`）

## 这个 demo **没有**证明什么

这个 demo 走的是 `yao_init` / `yao_step` / `yao_state` 的纯函数路径，
机器不回调宿主。早期 SPEC 里设计过四个回调端口（`颐` / `兑` / `需` / `观`），
**已在新版 SPEC §10 中降级为未采用方案**——理由见那一节。

配套的 `.h` 由 `--header` 一并生成，`host.c` 直接 `#include "traffic.h"`，
不再手工声明原型与事件号。
